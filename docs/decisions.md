# 実装決定事項(要件定義 v1.0 への補足)

2026-08-05 キックオフ時にユーザーと合意した、要件定義の曖昧箇所に対する決定。
`docs/requirements.md` と併せて仕様の一部として扱う。

## A. state.json の記録範囲
- state.json には**通知済みの状態のみ**を記録する
- `min_discount` 未満のセールは記録しない
- → 閾値未満(例 10%)から閾値以上(例 25%)に上がった場合は「新規セール」として通知される

## B. 割引率が下降した場合
- state は**通知済みの最高割引率を保持**し、下降時は更新しない
- → 同一セール期間内に 90% → 50% → 90% と変動しても再通知しない

## C. セール終了時のエントリ削除
- 価格取得に**成功**して `discount_percent == 0`(またはセール対象外)と確認できたエントリは**削除**する
- 価格取得に**失敗**したゲームのエントリは維持する(FR-04 の取りこぼし回復と両立)

## D. max_notify 超過分(「他 N 件」)の扱い
- 超過分は**通知済みにしない**
- → 翌日以降、枠が空けば繰り上がって通知される

## E. テストフレームワーク
- pytest を **dev 専用依存**として使用(`requirements-dev.txt` に分離)
- 配布物の実行時依存は `requests` + `PyYAML` のみを維持

## G. 通知の表示形式(2026-08-07 追加)
- `config.yaml` に `notify_style` を追加(FR-06 の拡張)
  - `card`(既定): 1ゲーム1embed・ヘッダー画像付き(従来どおり)
  - `list`: 1行1ゲーム(割引率 / タイトルリンク / 定価 / 現在価格)のコンパクト表示
- ASCIIテーブル形式は不採用: コードブロック内はリンク不可・全角文字で列が崩れるため

## F. その他の確認済み事項
- 初回サマリーでは上位10件のみ列挙するが、state にはセール中**全件**を記録する
- エラーの Discord 通知は workflow の `if: failure()` ステップに集約し、Python 側は非ゼロ終了するのみ
- 「クラッシュしても last_run を更新」のため、`main.py` に state 更新専用サブコマンドを設け、
  workflow の `if: always()` ステップから呼ぶ
- workflow に `concurrency` グループを追加し、手動実行と cron の多重実行を防ぐ
